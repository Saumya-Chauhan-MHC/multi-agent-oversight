**What I found**

- `requirements-docs.txt` has `mkdocs-material>=9.5`, with no upper bound. The installed version is 9.7.7, which is the newest release on PyPI, so there is nothing newer to update to. `mkdocs` is 1.6.1, also the newest 1.x. MkDocs 2.0 isn't released yet.
- The banner is printed by mkdocs-material itself (`material/templates/__init__.py`) every time you run `mkdocs`. It's a notice about a future release, not a build error.
- The build passes (exit 0) with or without the banner.

**Options**

1. **Suppress the banner.** Set `NO_MKDOCS_2_WARNING=1` in the Makefile's `docs-build` and `docs-serve` targets, or export it in your shell. I tested this and the banner goes away while the build still succeeds. This is the smallest change, but it hides the notice, including the warning that MkDocs 2.0 will break plugins and theme overrides. This project uses the `search` plugin and custom CSS/JS overrides, so that matters later.
2. **Pin an older mkdocs-material**, such as `<9.7`. I haven't checked whether 9.6.x prints the banner. Pinning backward loses fixes, so I wouldn't do it just for a notice.
3. **Leave it alone.** The docs build is unaffected.

I'd go with option 1 if the noise bothers you, and I'd plan a migration check before any future MkDocs 2.0 upgrade. Tell me which you want and I'll make the change.

Unrelated to the banner, the build also reports that `components/index.md` isn't in the `nav` in `mkdocs.yml`. It's only an info message, but you may want to add it or remove the file.
